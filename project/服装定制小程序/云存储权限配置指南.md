# 云存储权限配置指南

## 问题现状
- ✅ 开发者端：能看到图片
- ❌ 体验用户端：看不到图片

## 根本原因
云存储默认权限为私有，只有创建者（开发者）能访问。体验用户的 openid 不同，无法访问。

---

## 🎯 解决方案：修改云存储权限

### 方案A：公开读权限（推荐，最简单）

#### 1. 打开云开发控制台
在微信开发者工具中，点击顶部 **"云开发"** 按钮

#### 2. 进入云存储权限设置
左侧菜单 → **云存储** → **设置** → **权限设置**

#### 3. 修改权限规则
将规则修改为：

```json
{
  "read": true,
  "write": "auth.openId != null"
}
```

**说明**：
- `"read": true` - **所有人可读**（包括体验用户）
- `"write": "auth.openId != null"` - **只有登录用户可写**

#### 4. 保存并测试
点击"确定"保存，然后刷新体验版小程序。

**预期结果**：体验用户能看到所有图片 ✅

---

### 方案B：通过安全规则控制（更安全，但复杂）

如果不希望完全公开，可以使用安全规则：

```json
{
  "read": "auth.openId != null",
  "write": "auth.openId == resource.openId"
}
```

但这需要：
1. 每个图片上传时记录用户 openid
2. 修改 `CloudImageUtil` 为云函数代理方式
3. 云函数验证权限后返回临时链接

**不推荐**：实现复杂，免费版云函数调用次数有限。

---

## ⚠️ 安全说明

### 公开读是否安全？
**对于你的场景（产品图片）是安全的**，因为：

1. ✅ **产品图片本身就是公开内容**
   - 用户在你的小程序中都能看到
   - 不存在隐私问题

2. ✅ **无法通过 URL 直接访问**
   - `cloud://` URL 需要微信环境
   - 浏览器无法直接访问

3. ✅ **仍然有写入保护**
   - 只有登录用户能上传
   - 不会被人恶意填充

### 什么时候需要保护？
如果你的图片包含：
- ❌ 用户个人信息（头像、身份证）
- ❌ 付费内容（设计稿、文档）
- ❌ 敏感信息（合同、协议）

那就需要用**方案B**的云函数代理方式。

## 🔧 如何验证权限已生效

### 1. 查看权限规则
云开发控制台 → 云存储 → 设置 → 权限设置

应该显示：
```
读权限: 所有用户
写权限: 仅创建者及管理员
```

### 2. 测试体验版
1. 上传小程序体验版
2. 用体验者账号扫描体验版二维码
3. 查看图片是否显示

### 3. 查看控制台
体验版控制台不应有权限错误：
- ✅ 无 `errCode: -1` 错误
- ✅ 无 `permission denied` 错误

## 📝 常见问题

### Q1: 修改权限后多久生效？
**A**: 立即生效，无需重新上传小程序

### Q2: 会不会影响正式版？
**A**: 不会，权限规则对所有版本（开发版、体验版、正式版）生效

### Q3: 如何撤销公开读权限？
**A**:
```json
{
  "read": "auth.openId != null",
  "write": "auth.openId == resource.openId"
}
```

### Q4: 图片会被盗链吗？
**A**: 不会。`cloud://` URL 只能在微信小程序环境中使用，浏览器无法访问。

## 💡 删除临时链接转换代码（可选）

如果权限改为公开读，可以简化代码：

### 选项1：保留转换代码（推荐）
**优点**：
- 以后如果需要保护图片，随时可以改回来
- 对现有代码无影响
- 缓存机制仍然有效

**操作**：无需修改代码

### 选项2：删除转换代码
**优点**：
- 代码更简洁
- 减少网络请求
- 加载更快

**操作**：
1. 删除 `CloudImageUtil.preloadImages()` 调用
2. 直接使用原始 `mockData` 数据

**示例**：
```javascript
// 之前
const banners = await CloudImageUtil.preloadImages(mockData.banners);

// 之后（公开读权限）
const banners = mockData.banners; // 直接使用
```
