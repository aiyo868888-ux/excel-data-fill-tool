# Markdown 文档链接最佳实践

## 📋 文档说明

本文档说明了如何在 Markdown 文件中正确使用链接，以确保 AI (Claude) 能够有效利用文档内容。

---

## 🎯 核心原则

### ✅ 好的做法

**1. 使用 `@` 引用本地文件**
```markdown
详细文档：@docs/specification.md
```
- ✅ AI 能按需读取
- ✅ 节省上下文
- ✅ 完全可用

**2. 写出核心内容 + 链接**
```markdown
## 核心概念

这里是重要的核心内容...

## 完整文档
详细信息：@docs/full-spec.md
或访问：https://example.com/docs
```
- ✅ 有关键信息可用
- ✅ 指向完整文档
- ✅ 告诉如何获取更多内容

**3. 提供操作指南**
```markdown
## 完整规范

官方文档：https://example.com/spec

**如何获取**：
- 在对话中告诉我："请访问这个网址并总结"
- 我会使用 WebFetch 工具获取内容
```
- ✅ 说明了如何访问
- ✅ 告诉用户如何与 AI 交互
- ✅ 提供了基本概念

### ❌ 不好的做法

**1. 纯链接（无其他内容）**
```markdown
# 文档标题

完整内容：https://example.com/docs
```
- ❌ AI 无法访问链接
- ❌ 文档形同虚设
- ❌ 浪费文件位置

**2. 大量复制外部内容**
```markdown
# 文档标题

[复制了 5000 行的在线文档内容...]
```
- ❌ 浪费上下文
- ❌ 难以维护
- ❌ 容易过时

## 📊 对比表

| 方式 | 上下文占用 | AI 能否使用 | 维护成本 | 推荐度 |
|------|-----------|------------|---------|--------|
| **纯链接** | 极少 | ❌ 不能 | 低 | ⭐ |
| **完整复制** | 很多 | ✅ 能 | 高 | ⭐⭐ |
| **@ 引用** | 少 | ✅ 能 | 低 | ⭐⭐⭐⭐⭐ |
| **摘要+链接** | 中等 | ✅ 能 | 中 | ⭐⭐⭐⭐⭐ |
| **操作指南+链接** | 中等 | ✅ 能 | 低 | ⭐⭐⭐⭐ |

## 🔧 实战示例

### 示例 1：外部规范文档

**❌ 之前（不好）**：
```markdown
# Agent Skills Spec

The spec is now located at <https://agentskills.io/specification>
```

**✅ 之后（好）**：
```markdown
# Agent Skills 开发指南

## 什么是 Agent Skills？

Agent Skills 是 Claude Agent SDK 的功能扩展机制...

## 快速开始

### 1. 创建技能目录
```bash
mkdir -p skills/my-skill
```

### 2. 编写配置文件
...

## 完整规范

官方规范：https://agentskills.io/specification

**获取详细规范**：
- 在对话中告诉我："请访问 Agent Skills 规范网站"
- 我会使用 WebFetch 工具获取并总结
```

### 示例 2：本地 API 文档

**❌ 之前（不好）**：
```markdown
# API 文档

完整 API 参考见 @docs/api/reference.md
```

**✅ 之后（好）**：
```markdown
# API 文档

## 核心 API

### GET /api/users
获取用户列表
- 参数：无
- 返回：用户数组

### POST /api/users
创建新用户
- 参数：{name, email}
- 返回：创建的用户对象

## 完整 API 参考

详细文档：@docs/api/reference.md
```

## 💡 设计思路

### 1. 信息分层

```
第1层：核心要点（必须记住）
  ↓
第2层：常用信息（经常需要）
  ↓
第3层：详细文档（按需查阅）
```

**实现方式**：
- 第1层：直接写在主文件
- 第2层：用 `@` 引用
- 第3层：外部链接 + 访问说明

### 2. 按需加载

```markdown
# 主文档（小）
## 概述
核心内容...

## 详细文档
- API 文档：@docs/api.md
- 配置指南：@docs/config.md
- 故障排查：@docs/troubleshooting.md
```

**优点**：
- 主文件小（节省上下文）
- 详细文档按需读取
- 清晰的文档结构

### 3. 用户友好

```markdown
## 完整规范

官方文档：https://example.com/spec

**如果您需要详细信息**：
1. 访问上面的网址
2. 或在对话中告诉我："请获取这个规范的内容"
3. 我会帮您读取并总结
```

**好处**：
- 用户知道如何获取更多信息
- 说明了 AI 的能力
- 提供了多种方式

## 🎯 最佳实践总结

### 对于外部文档

**不要**：
```markdown
# 文档标题

完整内容：https://example.com/docs
```

**应该**：
```markdown
# 文档标题

## 核心概念
[写出最重要的内容]

## 完整文档
在线版本：https://example.com/docs

**如何获取**：
- 直接访问网址
- 或在对话中要求我访问并总结
```

### 对于本地文档

**不要**：
```markdown
完整内容见 @docs/very-long-file.md
```

**应该**：
```markdown
## 核心要点
[关键信息]

## 详细说明
完整文档：@docs/very-long-file.md
```

### 判断标准

**问自己三个问题**：
1. ✅ AI 能理解这个文件的基本内容吗？
2. ✅ 需要更多信息时，AI 知道去哪里找吗？
3. ✅ 用户知道如何与 AI 交互获取更多信息吗？

**如果都是"是"，那就是好文档！**

## 🔍 实施建议

### 步骤 1：审查现有文档

找出所有只有链接的文件：
```bash
# 查找包含 URL 的 Markdown 文件
grep -r "http://" docs/
grep -r "https://" docs/
```

### 步骤 2：分类处理

**对于外部链接**：
- 添加核心概念
- 添加访问说明
- 或考虑删除（如果不需要）

**对于本地文件引用**：
- 确保 `@` 语法正确
- 添加摘要信息
- 检查文件路径

### 步骤 3：验证效果

测试 AI 是否能正确使用文档：
```
用户：根据 @docs/spec.md 创建一个新项目
AI：应该能正确读取并使用文档
```
