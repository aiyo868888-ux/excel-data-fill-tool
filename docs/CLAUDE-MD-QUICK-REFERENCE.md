# CLAUDE.md 编辑快速参考

## 🎯 一页纸总结

### ✅ 正确方式

| 符号 | 用法 | 示例 | 效果 |
|------|------|------|------|
| **`@`** | 引用本地文件 | `@docs/api.md` | AI 按需读取 |
| **直接写** | 核心内容 | 写出重要原则 | 每次对话都可见 |
| **链接+说明** | 外部文档 | 链接+如何访问 | 告诉用户如何获取 |

---

### ❌ 错误方式

| 方式 | 示例 | 问题 |
|------|------|------|
| **纯链接** | `https://example.com` | AI 无法访问 |
| **完整复制** | [复制 5000 行] | 浪费上下文 |
| **复杂路径** | `@docs/../../file.md` | 难以维护 |

---

## 📐 结构模板

### 小项目（< 10 文件）

```markdown
# 项目名

## 概述
[2-3 句话]

## 快速开始
[安装和运行命令]

## 核心功能
[列出 3-5 个功能]

## 规范
[重要规则]
```

**目标**：所有信息在一个文件，< 300 行

---

### 中型项目（10-50 文件）

```markdown
# 项目名

## 概述
[简短描述]

## 快速开始
[安装步骤]

## 核心规范
- API 文档：@docs/api.md
- 配置指南：@docs/config.md
- 测试指南：@docs/testing.md

## 常见问题
@docs/faq.md
```

**目标**：主文件 < 200 行，详细文档分离

---

### 大型项目（> 50 文件）

```markdown
# 项目名

## 快速导航
- 入门：@docs/getting-started.md
- 开发：@docs/development/index.md

[Top 10 原则]

@docs/INDEX.md
```

**目标**：主文件 < 100 行，清晰索引

## 💡 三步法

### 1️⃣ 写核心内容

**问自己**：这个信息每次对话都需要吗？
- ✅ 是 → 写在 CLAUDE.md
- ❌ 否 → 用 `@` 引用

**示例**：
```markdown
## 核心原则
1. 解释术语
2. 说明原因
3. 提供示例
```

---

### 2️⃣ 用 `@` 引用详细文档

**问自己**：这个内容有多长？
- 短（<50 行）→ 可以直接写
- 长（>50 行）→ 用 `@` 引用

**示例**：
```markdown
## API 文档
完整 API 参考：@docs/api-reference.md
```

---

### 3️⃣ 外部链接加说明

**问自己**：AI 能访问这个链接吗？
- ❌ 不能 → 添加访问说明

**示例**：
```markdown
## 官方文档
完整规范：https://example.com/spec

**获取方式**：
- 访问上面的网址
- 或在对话中要求我访问并总结
```

## 📊 对比示例

### ❌ 之前（不好）

```markdown
# 项目文档

## 所有规范
[这里写了 800 行...]

## 所有文档
[又写了 600 行...]

总长度：1400 行
```

**问题**：
- ❌ 太长
- ❌ 难以找到重点
- ❌ 浪费上下文

---

### ✅ 之后（好）

```markdown
# 项目文档

## 核心原则
1. 原则一
2. 原则二
3. 原则三

## 详细文档
- 规范：@docs/standards.md
- 指南：@docs/guides.md
- FAQ：@docs/faq.md

总长度：150 行
```

**优点**：
- ✅ 精简
- ✅ 重点突出
- ✅ 节省 90% 上下文

## 🎯 记住这些

### ✅ DO（这样做）

```markdown
1. 核心内容 → 直接写
2. 详细文档 → @docs/file.md
3. 外部链接 → 添加访问说明
4. 文件大小 → < 500 行
```

### ❌ DON'T（别这样做）

```markdown
1. 纯链接 → https://example.com
2. 完整复制 → [5000 行内容]
3. 复杂路径 → @docs/../../file.md
4. 超长文件 → > 1000 行
```
