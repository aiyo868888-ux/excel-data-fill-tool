# Whisper 语音识别性能说明

## 📊 处理速度对比

### 不同模型的处理速度

| 模型 | 相对实时速度 | 20分钟音频处理时间 | 准确度 | 内存占用 |
|------|-------------|-----------------|-------|---------|
| **Tiny** | ~32x（最快）| **~40秒** | ⭐⭐ | ~1GB |
| **Base** | ~3x（推荐） | **~7分钟** | ⭐⭐⭐ | ~1.5GB |
| **Small** | ~2x | **~10分钟** | ⭐⭐⭐⭐ | ~2GB |
| **Medium** | ~1x | **~20分钟** | ⭐⭐⭐⭐⭐ | ~5GB |
| **Large** | ~0.7x | **~30分钟** | ⭐⭐⭐⭐⭐⭐ | ~10GB |

## 💡 性能优化建议

### 1. 选择合适的模型

**快速测试**：
- 使用 **Tiny** 模型
- 处理速度快 32 倍
- 适合快速预览

**日常使用**：
- 使用 **Base** 模型（推荐）
- 速度和准确度平衡
- 中文识别效果好

**高准确度需求**：
- 使用 **Small** 或 **Medium**
- 专业场合使用

### 2. 文件大小与处理时间

**音频时长估算**：
```
MP3 格式（128kbps）：
- 1MB ≈ 1 分钟音频
- 20MB ≈ 20 分钟音频

Base 模型处理时间：
- 20 分钟音频 ≈ 7 分钟处理时间
- 1 小时音频 ≈ 20 分钟处理时间
```

### 3. 禁用不需要的功能

**word_timestamps=True**（当前设置）：
- ✅ 优点：可以生成精确的字幕时间戳
- ❌ 缺点：处理速度**慢 2-3 倍**

**word_timestamps=False**：
- ✅ 优点：处理速度快 2-3 倍
- ❌ 缺点：只有句子级时间戳，没有词级时间戳

### 4. 实际案例

**案例 1：20MB 音频文件（约20分钟）**

使用 Base 模型 + word_timestamps=True：
- 预计处理时间：**15-20 分钟**
- 如果关闭 word_timestamps：**7-10 分钟**

使用 Tiny 模型 + word_timestamps=False：
- 预计处理时间：**1-2 分钟**

## ⚠️ 当前问题

从日志分析，您的文件处理了超过1小时，可能是：

1. **word_timestamps=True 导致** - 速度慢 2-3 倍
2. **可能是长音频** - 超过1小时的录音
3. **CPU 性能限制** - 单线程处理

## 🚀 建议优化

1. **添加模型选择**：在界面上提供 Tiny 选项
2. **关闭词级时间戳**：对于普通字幕，句子级时间戳足够
3. **显示预估时间**：上传后立即显示预计处理时间
4. **进度条优化**：添加更详细的进度信息

## 📝 代码修改建议

### 选项 1：关闭词级时间戳（推荐）

```python
result = self.model.transcribe(
    audio_path,
    language='zh',
    task='transcribe',
    word_timestamps=False  # 改为 False，速度快 2-3 倍
)
```

### 选项 2：添加快速模式

```python
# 前端添加"快速模式"选项
# 后端根据选择使用不同模型
if fast_mode:
    model_size = 'tiny'
    word_timestamps = False
else:
    model_size = 'base'
    word_timestamps = True
```

## 🎯 总结

- **20MB 音频** ≈ **20分钟录音**
- **Base 模型** ≈ **7分钟处理**（无词级时间戳）
- **Tiny 模型** ≈ **1分钟处理**（快速预览）

建议用户：
1. 先用 **Tiny** 模型快速预览
2. 确认内容后，用 **Base** 模型重新处理
