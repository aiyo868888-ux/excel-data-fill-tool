# Ralph Loop 手动使用方法

## 🔄 当插件命令不可用时

如果您暂时无法使用 `/ralph-loop` 命令，可以手动实现相同的效果。

---

## 方法 1：手动迭代（推荐）

### 工作原理

```
给 Claude 任务 → Claude 工作 → 审查结果 → 重新输入相同任务 → 重复
```

### 具体步骤

**第 1 次迭代**：

在 Claude Code 中输入：

```
创建一个简单的计算器：
1. 创建 calculator.py 文件
2. 实现加减乘除四个函数
3. 创建 test_calculator.py 测试文件
4. 编写至少 5 个测试用例
5. 每次迭代运行 pytest 验证
```

**第 2 次迭代**：

等 Claude 完成后，再次输入**完全相同的任务描述**：

```
创建一个简单的计算器：
1. 创建 calculator.py 文件
2. 实现加减乘除四个函数
3. 创建 test_calculator.py 测试文件
4. 编写至少 5 个测试用例
5. 每次迭代运行 pytest 验证
```

**关键点**：
- ✅ 使用**完全相同**的任务描述
- ✅ Claude 会看到之前创建的文件
- ✅ 基于上次结果继续改进
- ✅ 重复直到满意为止

**停止条件**：
- 所有测试通过
- 功能完整实现
- 或重复 10-20 次后手动停止

## 方法 2：使用 Bash 脚本（原版 Ralph）

### 准备工作

创建一个任务文件 `task.txt`：

```bash
cat > task.txt << 'EOF'
创建一个简单的计算器：
1. 创建 calculator.py 文件
2. 实现加减乘除四个函数
3. 创建 test_calculator.py 测试文件
4. 编写至少 5 个测试用例
5. 每次迭代运行 pytest 验证
EOF
```

### 运行循环

```bash
# 限制迭代次数（例如 10 次）
for i in {1..10}; do
    echo "=== 迭代 $i ==="
    cat task.txt
    # 这里需要手动调用 Claude Code
    sleep 1
done
```

**注意**：这种方法需要 Claude Code CLI 版本支持。

## 方法 3：利用 Git 历史

### 步骤

1. **第 1 次迭代**：
   ```
   创建计算器应用，包含测试
   ```

2. **提交到 Git**：
   ```bash
   git add .
   git commit -m "Iteration 1: Basic structure"
   ```

3. **第 2 次迭代**：
   ```
   继续改进计算器应用，添加更多测试用例
   ```

4. **提交到 Git**：
   ```bash
   git commit -m "Iteration 2: Added more tests"
   ```

5. **重复**，查看进度：
   ```bash
   git log --oneline
   ```

## 方法 4：使用记事本记录迭代

### 创建迭代日志文件

创建 `iterations.md`：

```markdown
# Ralph Loop 手动迭代日志

## 迭代 1
**任务**：创建计算器
**结果**：创建了 calculator.py，基本功能实现
**下次改进**：添加测试用例

## 迭代 2
**任务**：创建计算器
**结果**：添加了 test_calculator.py，3 个测试用例
**下次改进**：增加测试覆盖率

## 迭代 3
**任务**：创建计算器
**结果**：所有测试通过
**状态**：✅ 完成
```

### 每次迭代后

1. 检查完成情况
2. 记录到 `iterations.md`
3. 决定是否继续
4. 如果继续，重新输入任务描述

## 💡 最佳实践

### 1. 使用一致的任务描述

每次迭代使用**完全相同**的描述：

```
✅ 好：
"创建计算器应用，包含测试和文档"
"创建计算器应用，包含测试和文档"
"创建计算器应用，包含测试和文档"

❌ 不好：
"创建计算器"
"改进计算器"
"优化计算器代码"
```

### 2. 设置明确的完成标准

```
任务：创建计算器应用

完成标准：
- ✅ calculator.py 文件存在
- ✅ 实现加减乘除功能
- ✅ test_calculator.py 存在
- ✅ 至少 5 个测试用例
- ✅ 所有测试通过

最大迭代次数：10 次
```

### 3. 使用 Git 追踪进度

```bash
# 每次迭代后提交
git add .
git commit -m "Iteration N: 描述"

# 查看进度
git log --oneline

# 对比迭代
git diff HEAD~2 HEAD
```

### 4. 监控文件变化

```bash
# 查看最近修改的文件
ls -lt | head -10

# 查看文件内容
cat calculator.py

# 运行测试
pytest test_calculator.py -v
```

## 📊 迭代检查清单

每次迭代后检查：

- [ ] 文件是否创建/修改？
- [ ] 功能是否改进？
- [ ] 测试是否通过？
- [ ] 是否达到完成标准？
- [ ] 是否需要继续迭代？

### 决策树

```
迭代完成
   │
   ├─ 任务完成？
   │   ├─ 是 → ✅ 停止
   │   └─ 否 ↓
   │
   ├─ 有进展？
   │   ├─ 是 → 继续
   │   └─ 否 ↓
   │
   └─ 达到最大迭代次数？
       ├─ 是 → 停止，记录阻塞问题
       └─ 否 → 继续
```

## 🔄 与自动 Ralph Loop 的对比

| 特性 | 自动 Ralph Loop | 手动 Ralph Loop |

| **需要重启** | ✅ 需要重启加载插件 | ❌ 不需要 |

| **可用性** | ⚠️ 取决于插件 | ✅ 总是可用 |
| **适用场景** | 长时间任务 | 短时间任务或测试 |

## 🎓 总结

**手动 Ralph Loop** 核心理念：

> **使用相同的任务描述多次迭代，每次都基于上次的结果改进**

**关键要点**：

1. ✅ 任务描述必须**完全相同**
2. ✅ Claude 会看到之前的文件
3. ✅ 每次迭代都应该有进展
4. ✅ 设置明确的完成标准
5. ✅ 使用 Git 追踪进度

**何时使用**：

- 插件命令不可用时 ✅
- 想要更精细的控制时 ✅
- 学习 Ralph Loop 原理时 ✅
- 短时间任务（< 5 次迭代） ✅
