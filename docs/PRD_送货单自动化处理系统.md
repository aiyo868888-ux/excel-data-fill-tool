## 1. 文档概述

### 1.1 目的
本文档旨在定义"送货单自动化处理系统"的完整产品需求，为开发团队提供清晰的实施指导，确保产品满足业务需求并提供良好的用户体验。

### 1.2 范围
- **包含**: Windows 桌面应用的核心功能、界面设计、数据处理逻辑
- **不包含**: 移动端支持、云端同步、多用户协作功能

### 1.3 定义与缩写
- **报表文件**: 月度汇总 Excel 文件，包含入库单、交接单和供货商记录
- **送货单**: 供货商提供的每日送货 Excel 文件（.xls 或 .xlsx 格式）
- **供货商**: 提供商品的供应商，每个供货商在报表中占 7 列
- **入库单**: 入库记录区域（A-F 列，共 6 列）
- **交接单**: 当日所有送货汇总记录（R-W 列，共 6 列）

## 2. 产品背景与目标

### 2.1 业务背景
当前处理流程中，仓库管理人员需要手动将多个供货商的送货单数据整合到月度报表中，存在以下问题：
- **效率低下**: 每月需要处理数百个送货单，手动复制粘贴耗时耗力
- **容易出错**: 人工操作容易出现数据错位、漏填、重复等问题
- **难以追溯**: 手工操作缺乏审计追踪，问题难以定位
- **扩展性差**: 供货商数量变化时需要重新设计报表结构

### 2.2 产品目标
#### 主要目标
1. **效率提升**: 将单日数据处理时间从 30 分钟降低至 5 分钟以内（提升 80%+）
2. **准确性保障**: 消除人工操作错误，数据准确率达到 99.9%
3. **操作简化**: 通过向导式流程降低学习成本，新用户 10 分钟内上手
4. **灵活配置**: 支持动态调整供货商列表，无需修改代码

#### 成功指标
- 用户完成时间（处理单月数据）: < 2 小时
- 数据错误率: < 0.1%
- 用户满意度: > 4.5/5.0
- 系统崩溃率: < 0.5%

#### 功能 1: 报表文件管理（P0 - 必须有）

**功能描述**: 用户能够打开、保存和管理月度报表文件

**用户故事**:
> 作为仓库管理员，我想要打开月度报表文件，以便开始处理当月的送货单

**验收标准**:
- [x] 支持打开 .xlsx 和 .xls 格式文件
- [x] 自动检测报表结构（工作表 1-31）
- [x] 验证文件格式正确性
- [x] 显示最近打开的文件列表（最多 5 个）
- [x] 保存时自动备份原文件（备份后缀 .bak）
- [x] 保存时提示文件名冲突

**数据规格**:
```python
# 报表结构定义
报表结构 = {
    "工作表数量": 31,
    "工作表命名": "1" ~ "31",
    "入库单列": "A:F" (6列),      # 品名、单位、数量、单价、金额、备注
    "交接单列": "R:W" (6列),     # 汇总当天所有送货
    "供货商起始列": "AC" (第29列),
    "供货商列宽": 7列,
    "供货商数量": 可配置
}

# 送货单结构定义
送货单结构 = {
    "工作表命名": 数字日期（1-31）,
    "数据列": "A:E" (5列),
    "列定义": {
        "A列": "品名",
        "B列": "单位",
        "C列": "数量",
        "D列": "单价",
        "E列": "总计"
    }
}
```

**界面元素**:
- 文件菜单: 打开、保存、另存为、最近文件
- 启动页面: 快速打开最近文件
- 状态栏: 显示当前文件路径和修改状态

#### 功能 3: 送货单导入与处理（P0 - 必须有）

**功能描述**: 用户选择送货单文件，系统识别日期并引导用户选择供货商，自动完成数据复制

**用户故事**:
> 作为仓库管理员，我想要导入送货单并选择对应的供货商，以便系统自动将数据填入正确位置

**验收标准**:
- [x] 支持批量选择多个送货单文件
- [x] 自动从工作表名称提取日期（支持"1"、"01"、"1日"等格式）
- [x] 日期格式错误时提示用户手动选择
- [x] 显示数据预览（A-E 列内容）
- [x] 下拉框选择供货商（支持搜索）
- [x] 单个文件处理时间 < 2 秒
- [x] 支持跳过特定文件
- [x] 处理完成后显示汇总信息

**处理流程**:
```
1. 用户选择送货单文件
   ↓
2. 系统读取并验证文件格式
   ↓
3. 系统提取工作表名称并识别日期
   ↓
4. 系统读取 A-E 列数据
   ↓
5. 用户选择供货商（必选）
   ↓
6. 系统验证数据完整性
   ↓
7. 系统复制数据到目标位置
   ↓
8. 系统更新交接单（R-Z 列）
   ↓
9. 显示处理结果（成功/失败）
```

**数据验证规则**:
```python
验证规则 = {
    "工作表名称": r"^[0-9]{1,2}$|^[0-9]{1,2}日$",  # 1-31 或 1日-31日
    "数据行数": ">= 1",
    "A列": "非空（商品名称）",
    "B列": "非空（规格型号）",
    "C列": "数值（数量）",
    "D列": "数值（单价）",
    "E列": "数值（金额）"
}
```

**界面元素**:
- 批量导入对话框: 文件列表 + 供货商选择列
- 进度条: 显示处理进度（已处理 X/总计 Y）
- 数据预览窗格: 显示当前文件内容
- 操作按钮: 开始处理、跳过、取消、完成

## 7. 数据验证与错误处理

### 7.1 数据验证层级

#### 层级 1: 文件级验证
```python
文件验证规则 = {
    "文件存在性": True,
    "文件格式": [".xlsx", ".xls"],
    "文件大小": "< 10MB",
    "文件可读性": "非损坏文件",
    "工作表存在性": "至少包含一个命名日期的工作表"
}
```

#### 层级 2: 结构验证
```python
结构验证规则 = {
    "工作表命名": r"^[0-9]{1,2}$|^[0-9]{1,2}日$",
    "日期范围": "1-31",
    "列数量": ">= 5（A-E列）",
    "数据行数": ">= 1"
}
```

#### 层级 3: 数据验证
```python
数据验证规则 = {
    "A列（商品名称）": {
        "类型": "字符串",
        "长度": "1-100字符",
        "必填": True
    },
    "B列（规格型号）": {
        "类型": "字符串",
        "长度": "0-50字符",
        "必填": False
    },
    "C列（数量）": {
        "类型": "数值",
        "范围": "> 0",
        "必填": True
    },
    "D列（单价）": {
        "类型": "数值",
        "范围": ">= 0",
        "必填": True
    },
    "E列（金额）": {
        "类型": "数值",
        "范围": ">= 0",
        "必填": True,
        "计算": "应等于 C列 × D列"
    }
}
```

#### 层级 4: 业务规则验证
```python
业务验证规则 = {
    "重复检测": "同一商品+同一日期不应重复",
    "供货商匹配": "供货商必须在配置列表中",
    "日期匹配": "工作表日期必须在1-31范围内",
    "金额一致性": "abs(金额 - 数量×单价) < 0.01",
    "总金额校验": "所有记录金额之和应等于交接单合计"
}
```

### 7.2 错误处理策略

#### 策略 1: 阻断式错误（必须修正）
- **触发条件**: 文件损坏、格式错误、必填项缺失
- **处理方式**: 暂停操作，强制用户修正
- **示例**: 工作表名称不是日期格式

#### 策略 2: 警告式错误（建议修正）
- **触发条件**: 金额计算偏差、疑似重复数据
- **处理方式**: 显示警告，用户可选择忽略
- **示例**: 数量×单价与金额相差 0.05 元

#### 策略 3: 提示式错误（可选修正）
- **触发条件**: 数据异常（如金额过大）、格式不规范
- **处理方式**: 记录日志，不中断流程
- **示例**: 单笔金额超过 10000 元

### 7.3 错误消息设计

**原则**: 清晰、具体、可操作

**格式**: `[错误代码] 错误描述`
- **位置**: 第几行、第几列、哪个文件
- **原因**: 具体问题
- **建议**: 如何修正

**示例**:
```
❌ [E003] 数值格式错误
📄 文件: 送货单_05.xlsx
📊 位置: 第3行，C列（数量）
🔍 问题: 包含非数字字符 "100件"
💡 建议: 请输入纯数字，例如 "100"
[修正] [忽略] [查看详情]
```

### 7.4 数据完整性保障

**机制 1: 事务性处理**
- 处理过程中发生错误，自动回滚所有修改
- 保证数据要么全部成功，要么全部失败

**机制 2: 自动备份**
- 每次保存前自动创建备份文件
- 保留最近 5 个版本

**机制 3: 校验和验证**
- 保存后自动计算数据校验和
- 下次打开时验证数据完整性

#### 可靠性保障机制:
1. **自动备份**: 每次保存前创建备份
2. **事务处理**: 数据修改原子化
3. **校验机制**: 数据完整性检查
4. **错误日志**: 详细记录错误信息
5. **崩溃恢复**: 自动检测并恢复未保存数据

## 10. 风险评估与缓解

### 10.1 技术风险

#### 风险 1: Excel 文件兼容性问题
**风险等级**: 🟡 中等

**描述**:
不同版本的 Excel 可能存在格式差异，导致文件读取错误或数据丢失。

**影响**:
- 无法读取某些送货单文件
- 数据显示异常
- 用户无法正常工作

**概率**: 30%

**缓解措施**:
1. ✅ 支持多种文件格式（.xlsx, .xls）
2. ✅ 使用成熟的 Excel 处理库（openpyxl, xlrd）
3. ✅ 提供文件格式转换工具
4. ✅ 详细的错误提示和解决建议
5. ✅ 测试覆盖主流 Excel 版本（2016, 2019, 2021）

**应急方案**:
- 提供手动导入 CSV 格式功能
- 提供详细的 Excel 格式检查工具

---

#### 风险 2: 大文件处理性能问题
**风险等级**: 🟡 中等

**描述**:
当报表文件包含大量数据（如几千条记录）时，可能导致界面卡顿或响应缓慢。

**影响**:
- 用户体验下降
- 操作等待时间过长
- 可能导致系统假死

**概率**: 40%

**缓解措施**:
1. ✅ 实现懒加载机制（按需加载数据）
2. ✅ 使用异步处理（后台线程执行 I/O 操作）
3. ✅ 显示进度条和加载状态
4. ✅ 设置性能监控和告警
5. ✅ 优化算法复杂度（避免 O(n²)）

**应急方案**:
- 提供数据分页功能
- 允许用户选择处理范围（如仅处理某几天）

---

#### 风险 3: 数据丢失风险
**风险等级**: 🔴 高

**描述**:
程序崩溃、断电、用户误操作等可能导致数据丢失。

**影响**:
- 用户工作成果丢失
- 需要重新处理数据
- 用户信任度下降

**概率**: 10%

**缓解措施**:
1. ✅ 自动备份机制（每次保存前）
2. ✅ 保留多个历史版本（5 个）
3. ✅ 事务性处理（全部成功或全部失败）
4. ✅ 崩溃恢复机制（检测未保存数据）
5. ✅ 定期自动保存（每 5 分钟）

**应急方案**:
- 提供数据恢复工具
- 从备份文件恢复数据

---

#### 风险 4: 第三方库依赖风险
**风险等级**: 🟢 低

**描述**:
使用的第三方库（如 openpyxl）可能出现 bug、停止维护或兼容性问题。

**影响**:
- 功能异常
- 安全漏洞
- 需要重写代码

**概率**: 15%

**缓解措施**:
1. ✅ 选择成熟、活跃维护的库
2. ✅ 固定库版本（避免自动升级）
3. ✅ 定期更新库版本
4. ✅ 准备替代方案（如多个 Excel 处理库）
5. ✅ 充分的集成测试

**应急方案**:
- 快速切换到备用库
- 发布补丁版本
