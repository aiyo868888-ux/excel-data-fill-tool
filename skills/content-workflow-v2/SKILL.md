# Content Workflow

基于 Dan Koe 方法论的模块化内容生产工作流系统，专注于将想法系统化地转化为高质量内容。

**核心特性**: 每个阶段都有明确的完成标准和用户确认机制，确保内容质量。

## 核心原则

- **验证优先创作** - 只扩展已经过验证的想法
- **框架优于灵感** - 用验证过的结构填充新想法
- **AI 是放大器** - 扩展思考边界，而非替代思考
- **系统化迭代** - 每周复盘，不断优化框架库
- **显式确认** - 每个阶段完成后等待用户确认

## 快速开始

### 基本工作流

```
想法捕获 → 素材整理 → 框架拆解 → 两阶段生成 → 多平台分发 → 音频转化 → 音频生成
   ↓确认      ↓确认      ↓确认      ↓确认        ↓确认        ↓确认       ↓确认
```

每个阶段完成后都会：
1. 输出结构化结果
2. 显示完成标记 ✅
3. 提供确认选项
4. 等待用户明确回复

### 7 大核心工具

位于 `assets/prompts/`：

1. **01-thought-capturer.md** - 想法捕获与验证
2. **02-material-organizer.md** - 素材整理浓缩
3. **03-framework-extractor.md** - 爆款框架逆向工程
4. **04-context-collector.md** - 上下文采集（阶段一）
5. **05-content-generator.md** - 内容生成（阶段二）
6. **06-audio-adapter.md** - 音频内容转化
7. **07-audio-generator.md** - 音频文件生成（TTSMaker + 自动化脚本）
   - 支持文本清理和预览
   - 用户确认后生成音频

## 确认协议

每个 Prompt 都遵循标准化的确认流程：

### 完成标记
```
【阶段名称】✅ 完成
```

### 结构化输出
每个阶段输出包含：
- 明确的分段标题
- 结构化的内容
- 完整性检查清单

### 确认选项
```
请回复以下选项之一：
1. "确认" - 接受结果，继续下一步
2. "修改 [部分]" - 调整特定内容
3. "重新 [操作]" - 重新执行当前阶段
```

### 用户响应
- 必须收到用户明确回复后才继续
- 不擅自进入下一阶段
- 不替用户做决定

### 场景 3: 多平台内容分发

**转化规则**：

| 源内容 | 目标平台 | 操作 |
|--------|----------|------|
| Newsletter 章节 | Twitter | 拆成 3-5 条推文，每条一个观点 |
| YouTube 脚本 | Twitter | 提取金句 + 数据 |
| Twitter 爆款 | Newsletter | 扩展成完整论证 |
| Twitter 系列 | YouTube | 脚本大纲 + 案例 |
| 长文/视频脚本 | 音频播客 | 改编为音频脚本（增加停顿、语气标注） |

```
内容生成 → 确认
  ↓

  ↓

  ↓

  ↓
```

1. 音频脚本改编（去视觉化、增加停顿）
2. 生成 TTSMaker 专用文本（清除标记）
3. 使用 TTSMaker 在线生成 MP3
4. 下载音频文件
5. 后期处理（Audacity 添加背景音乐）

## 核心概念

### 两阶段生成系统

**阶段一: 上下文采集**
- AI 像记者一样依次提问 6 个问题
- 每个问题等待回答后再问下一个
- 收集：主题、受众、独特角度、素材、框架、形式
- 全部收集完后总结并等待确认

**阶段二: 内容生成**
- 基于确认的信息生成 3 个不同版本
- 版本 A: 直接有力型（短句、绝对语）
- 版本 B: 故事共鸣型（有代入感）
- 版本 C: 挑战反常识型（制造张力）
- 推荐最佳版本并等待用户选择

### 框架模板

从爆款内容提取的可复用结构：

```
[钩子] 吸引注意力的开场
+
[冲突] 提出问题或矛盾
+
[转折] 连接词（然后/但是/然而）
+
[解决] 核心观点或方案
+
[升华] 令人难忘的金句
```

### 知识库结构

```
想法库 (ideas.json)
├── 主题
├── 类型: [推文/长文/视频/混合]
├── 评分: 共鸣度/独特性
└── 日期

素材库 (materials.json)
├── 主题
├── 核心观点
├── 金句
└── 日期

框架库 (frameworks.json)
├── 名称
├── 结构模板
├── 适用场景
└── 来源
```

### 音频生成工具：自动化脚本 + TTSMaker

**方案 1：自动化脚本（推荐）**

**脚本位置**：`scripts/tts_generator.py`

**特点**：
- ✅ 完全自动化，一键生成
- ✅ 使用 Edge TTS（免费，无需 API 密钥）
- ✅ 音质优秀，接近真人
- ✅ 支持多种中文语音
- ✅ 可调节语速
- ✅ 自动清理文本（移除标记）
- ✅ 生成前预览并确认

**快速使用**：
```bash
# 带确认（推荐）
python scripts/tts_generator.py "文本文件.txt"

# 跳过确认（快速生成）
python scripts/tts_generator.py "文本文件.txt" --no-confirm
```

**工作流程**：
1. 读取文本文件
2. 自动清理文本（移除 Markdown 标记、时间轴等）
3. 显示预览（前 50 行）
4. 等待用户确认
5. 生成音频文件

**详细文档**：查看 `scripts/README.md`

---

**方案 2：TTSMaker 在线工具**

- 官网：https://ttsmaker.com
- 类型：免费在线文本转语音工具
- 支持：中文（多种声音可选）
- 输出：MP3 音频文件
- 限制：免费版约 10000 字

**使用流程**：
1. 准备 TTSMaker 专用文本（清除所有标记）
2. 访问 TTSMaker 网站
3. 粘贴文本，选择声音（推荐 Xiaoxiao 女声或 Yunyang 男声）
4. 调节语速（推荐 0.85x - 0.9x）
5. 点击生成，等待 1-3 分钟
6. 下载 MP3 文件

**后期处理**（可选）：
- 使用 Audacity（免费）添加背景音乐
- 音量标准化（-16 LUFS 播客标准）
- 添加淡入淡出效果
- 导出最终音频文件

**适合场景**：
- 播客音频制作
- 上传到音频平台（喜马拉雅、小宇宙等）
- 需要永久保存的音频内容

## 每日执行节奏

### 2 小时创作块

- 09:00-09:10 - 回顾数据，选出最佳想法
- 09:10-09:50 - 完成主内容（Newsletter/视频脚本）
- 09:50-10:00 - 生成 3 条社交媒体内容
- 10:00-10:30 - 素材整理（视频/书籍 → AI 提取）
- 10:30-11:00 - 框架库维护（拆解 1 条爆款）

### 每周安排

- 周一: 制定主题清单
- 周二-周四: 日常创作
- 周五: 录制视频
- 周六: 复盘数据，更新框架库
- 周日: 休息 + 灵感收集

## 最佳实践

1. **先验证再扩展** - 用推文测试想法，表现好的扩展成长文
2. **建立框架库** - 拆解至少 10 条爆款，形成个人模板库
3. **定期复盘** - 每周分析哪些框架和话题表现最好
4. **素材整理** - 看完视频/书后立即用 AI 提取要点
5. **多平台互相喂养** - 每个平台的内容都能转化为其他平台
6. **音频覆盖** - 长文和视频脚本都可改编为音频，覆盖通勤场景
7. **明确确认** - 每个阶段完成后等待用户回复，不擅自推进
