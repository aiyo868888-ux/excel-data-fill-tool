# 问题记录与修复

## 2026-01-24 - 数据覆盖问题

### 问题描述
在执行图片表格识别并插入Excel时，新数据覆盖了原有的历史数据（第30-45行的"直管、方法兰"等数据被"空调机组"数据覆盖）。

### 问题根源

#### 1. 查找最后数据行的逻辑缺陷
- **问题**：虽然 `find_last_data_row()` 函数逻辑正确，但在实际执行时没有使用该函数
- **原因**：直接使用了 ExcelTool 的 `write_data` 操作，没有先调用 `find_last_row.py` 工具
- **后果**：误判最后数据行为第28行，实际上第30-49行都有数据

#### 2. 使用了覆盖式写入
- **问题**：`ExcelTool.write_data` 直接覆盖指定位置的数据
- **原因**：没有使用 `map_and_insert.py` 脚本，而是直接调用了 ExcelTool
- **后果**：第30-45行的原有数据被新数据覆盖

#### 3. 缺少用户确认环节
- **问题**：没有向用户展示最后数据行的内容并等待确认
- **原因**：流程中缺少这一关键步骤
- **后果**：用户无法在插入前发现错误

### 修复措施

#### 1. 增强 `find_last_data_row()` 函数
```python
def find_last_data_row(ws, start_row=5):
    """找到最后一个有数据的行（完整扫描，不遗漏任何数据）"""
    last_data_row = start_row - 1
    max_row = ws.max_row
    
    print(f"  [调试] 工作表 max_row: {max_row}")
    
    for row in range(start_row, max_row + 1):
        row_has_data = False
        for col in range(1, 14):
            cell_value = ws.cell(row=row, column=col).value
            if cell_value is not None and str(cell_value).strip() != "":
                row_has_data = True
                break
        
        if row_has_data:
            last_data_row = row
            print(f"  [调试] 第{row}行有数据")
    
    print(f"  [调试] 最终确定最后数据行: {last_data_row}")
    return last_data_row
```

**改进点**：
- 增加调试输出，显示扫描过程
- 明确检查每个单元格是否为空
- 输出最终确定的最后数据行

#### 2. 创建专用工具 `find_last_row.py`
- **功能**：安全地扫描整个工作表，准确定位最后数据行
- **输出**：所有有数据的行号、最后行内容、建议插入位置
- **用途**：在插入数据前必须先运行此工具

#### 3. 更新 Skill.md 工作流程
- **强制要求**：必须使用 `find_last_row.py` 工具
- **用户确认**：必须向用户展示最后数据行内容并等待确认
- **警告提示**：明确说明数据可能不连续，中间可能有空行

#### 4. 禁止直接使用 ExcelTool 写入
- **规则**：必须使用 `map_and_insert.py` 脚本
- **原因**：该脚本包含完整的查找、确认、追加逻辑
- **例外**：仅在用户明确指定插入位置时可以使用 ExcelTool

### 经验教训

1. **永远不要假设数据是连续的**
   - Excel表格中间可能有空行
   - 必须扫描到 `max_row` 才能确保不遗漏

2. **必须向用户确认关键信息**
   - 最后数据行的内容
   - 插入位置
   - 可能受影响的范围

3. **使用专用工具而非通用API**
   - `map_and_insert.py` 包含完整的安全检查
   - ExcelTool 是通用工具，缺少业务逻辑保护

4. **增加调试输出**
   - 显示扫描过程
   - 显示找到的数据行
   - 便于发现问题
