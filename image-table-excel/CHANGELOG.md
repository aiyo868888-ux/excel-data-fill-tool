# 修改日志

## [1.1.0] - 2026-01-24

### 🔴 重大修复
- **修复数据覆盖问题**：插入数据时不再覆盖历史内容
  - 问题：新数据覆盖了第30-45行的原有数据（直管、方法兰等）
  - 原因：没有完整扫描工作表，误判最后数据行位置
  - 解决：增强查找逻辑，强制用户确认，使用追加模式

### ✨ 新增功能
- **新增 `find_last_row.py` 工具**
  - 安全地扫描整个工作表
  - 显示所有有数据的行号和内容
  - 输出最后数据行的完整内容
  - 建议插入位置

### 🔧 代码改进
- **增强 `find_last_data_row()` 函数**（`map_and_insert.py`）
  - 增加调试输出，显示扫描过程
  - 明确检查每个单元格是否为空
  - 输出最终确定的最后数据行
  
- **改进插入逻辑**（`map_and_insert.py`）
  - 不使用 `insert_rows()`，改为直接追加
  - 在最后数据行+2的位置写入（+1为空行分隔）
  - 历史内容完全不受影响

- **更新 `update_excel_with_data.py`**
  - 移除 `ws.insert_rows()` 调用
  - 改用追加模式写入数据
  - 增加历史内容保护说明

### 🎯 流程改进
- **强制用户确认环节**
  - 必须向用户展示最后数据行内容
  - 必须等待用户确认插入位置
  - 提供清晰的确认提示模板

- **插入前检查清单**
  - 8项必做检查
  - 所有项都打勾才能执行

### 🔒 安全增强
- **历史数据保护**
  - 采用追加模式，不使用插入行功能
  - 已有数据的行号、格式、内容完全保持不变
  - 自动保留空行分隔

- **完整扫描保证**
  - 扫描范围：`range(5, ws.max_row + 1)`
  - 不因空行中断扫描
  - 不假设数据是连续的

### 📝 核心原则（新增）
1. 历史数据保护优先
2. 完整扫描工作表
3. 用户确认必需
4. 使用专用工具
5. 追加模式插入

### 🧪 测试场景

- 末尾有大量空行
